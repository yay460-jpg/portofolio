# Mine Services — Controlled Vocabulary and Transaction Matrix v1

## Status
- Stage: 1 — Data Model
- Contract: v1
- Purpose: close the remaining Stage 1 contract gaps before final schema lock
- Final lock: pending audit

## 1. Design Rules
1. Controlled values are contract data, not arbitrary UI labels.
2. IDs/codes are stable; display labels may change without changing historical meaning.
3. New values require contract review before production use.
4. A transaction type defines its mandatory references and measurement semantics.
5. Units must be explicit whenever a numeric measurement is stored.
6. Historical records retain the code that was valid when the transaction occurred.

## 8. Measurement Type and Unit
| Measurement Type | Unit | Typical use |
|---|---|---|
| OPERATING_TIME | h | Equipment operating duration |
| WORK_TIME | h | Service activity duration |
| DISTANCE | km | Road/hauling distance |
| VOLUME | m3 | Material/service volume |
| AREA | ha | Clearing/reclamation area |
| COUNT | unit | Discrete completed activities |
| FLOW_VOLUME | m3 | Pumped/dewatered volume where measured |

Rules:
- The transaction type determines which measurement types are valid.
- A numeric value without an explicit unit is invalid.
- Additional measurement types require contract review.

## 11. Event Time Rule
`event_date` is always required.
`event_time` is required when the transaction represents an interval/event whose order affects calculation, multiple events need temporal distinction, or operating-time records are used for fleet KPI calculations.
`event_time` may be omitted for daily aggregate transactions where the transaction contract explicitly permits daily granularity.

## 13. Rejected / Voided Reason
| Code | Meaning |
|---|---|
| INVALID_REFERENCE | Master reference invalid |
| INVALID_MEASUREMENT | Measurement/value/unit invalid |
| DUPLICATE | Duplicate transaction |
| DATA_ERROR | Other material data error |
| OPERATIONAL_CORRECTION | Authorized operational correction |

Production implementation must retain the reason code and explanatory note where required.

## 14. Responsibility Identity
`responsibility_id` must reference an organizational identity known to the Mine Services security/identity layer.
Free-text responsibility names are not authoritative.
The exact organizational identity schema is deferred to the architecture/security stages.

## 15. Audit Event Minimum
Material changes must produce an auditable event containing at least record/entity ID, action, actor, timestamp, reason when applicable, and previous state/reference when required for reconstruction.
The full immutable audit-event schema remains a later Audit-stage contract.

## 16. Stage 1 Decision
This vocabulary and matrix closes the principal contract gaps identified by Entity Contract v1 Audit while deliberately leaving implementation-level identity, persistence, and security schemas to later stages.
