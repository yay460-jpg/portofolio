# Rainfall / Hydrology Simulation Record Contract

**Workbook:** `Database/Mine-Services-Database-A3.xlsx`  
**Worksheet / entity:** `RainfallSimulation`  
**Active schema:** `A.3`  
**Status:** Record schema approved for the initial Rainfall Simulation implementation.

## Purpose

One row records one rainfall simulation scenario/run. The row retains input parameters, terrain identity, selected calculation options, compact aggregate outputs, and the model version used. It supports traceability without turning A3 into a raster or animation store.

The original `.ltdtm` / DTM / STR source remains unchanged. Grid-by-grid flow values and animation frames must not be written into this worksheet. If a future requirement needs portable full result grids, define a bounded result-file format and store a validated reference separately.

## Canonical headers

| Header | Meaning / unit | Rule |
|---|---|---|
| `simulation_id` | Stable unique ID for this simulation record | Primary key; required and immutable |
| `scenario_name` | Operator-readable scenario name | Required; maximum 120 characters |
| `status` | Record/run lifecycle state | Required: `DRAFT`, `RUNNING`, `COMPLETED`, `FAILED`, or `CANCELLED` |
| `topography_name` | Source `.ltdtm` or DTM package name | Required |
| `terrain_fingerprint` | SHA-256 digest identifying the exact terrain source | Optional until the loader exposes a stable fingerprint; if supplied, 64 hex characters |
| `rainfall_intensity_mm_hr` | Constant rainfall intensity in mm/hour | Required; finite and greater than zero |
| `rainfall_duration_min` | Scenario duration in minutes | Required; finite and greater than zero |
| `runoff_coefficient` | Fraction of rainfall assumed to become surface runoff | Required; range 0–1 |
| `grid_resolution_m` | Analysis grid cell size in metres | Required; finite and greater than zero |
| `flow_algorithm` | Flow-direction method identifier | Required; initial supported value: `D8` |
| `depression_treatment` | Handling of depressions/flats in the terrain model | Record schema accepts `FILL`, `BREACH`, or `PRESERVE`; Hydrology Engine v1 currently computes `FILL` and `PRESERVE` only. `BREACH` must not be marked completed until an implementation is validated. |
| `catchment_area_m2` | Analyzed catchment area in square metres | Optional until a catchment boundary is defined; if supplied, greater than zero |
| `total_rainfall_mm` | Total rainfall depth over the scenario | Optional output; mm |
| `estimated_runoff_volume_m3` | Estimated surface-runoff volume | Optional output; m³ |
| `max_flow_accumulation_cells` | Highest number of upstream cells contributing to a cell | Optional output; non-negative integer |
| `result_summary_json` | Compact JSON object with supplementary aggregate results | Optional; valid JSON object, maximum 30,000 characters |
| `model_version` | Version of the Hydrology calculation implementation | Required to distinguish algorithm versions |
| `created_at` | UTC timestamp when the record was created | Generated by the application; not supplied by callers |
| `updated_at` | UTC timestamp of the last record update | Generated by the application; not supplied by callers |
| `notes` | Human-readable assumptions or field notes | Optional; maximum 1,000 characters |

## Persistence rules

- The sheet is a first-class A3 entity and uses existing RuntimeAdapter CREATE / READ / UPDATE / DELETE operations and AuditLog behavior.
- The migration is idempotent: if the sheet is missing, the runtime adds the canonical header row before loading data. Existing sheets with valid headers and records are preserved.
- If a sheet with data has unexpected headers, initialization fails with `HEADER_MISMATCH:RainfallSimulation`; existing data must never be silently overwritten.
- The new entity is included in runtime snapshots and named datasets. Legacy A.3 snapshots/datasets predating this entity treat it as empty without discarding other records.
- Numerical outputs must be explicitly defined by the Hydrology model. An unavailable metric stays blank; it must not be filled with zero merely to make the row look complete.
- Save one row per scenario/run. Re-running with different rainfall inputs should create a new `simulation_id`, so historical runs remain comparable.
- Version the algorithm and calculation contract when assumptions, flow routing, depression handling, or runoff estimation changes.

## Scope boundary

This worksheet is a record schema, not proof that a hydrology model or flood-depth calculation exists. Hydrology Engine v1 now implements bounded TIN-to-grid sampling, D8 flow direction, flow accumulation, priority-flood depression filling, preserve-depression mode, and a constant-intensity rainfall/runoff-volume estimate. The engine is not yet connected to the loaded Topo3D mesh or the Rainfall toolbar. Flood depth, velocity, inundation boundaries, and engineering-grade drainage design require separate model methods, input data, and validation evidence.
